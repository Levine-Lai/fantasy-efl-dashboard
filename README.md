# Fantasy EFL 数据看板

2026-10-22 更新：EFL/FPL 双入口与每日采集已接通；补齐球队别名、姓名变体及按官方逐场 ID 核对的转会分段统计。缺失原因与逐人清单见 [更新核查报告](docs/update-audit-2026-10-22.md)。`npm run typecheck:fpl` 检查 FPL 类型。

## EFL / FPL 双模块

左上角切换 EFL / FPL。FPL 入口为 `fpl.html`，个人页为 `fpl-personal.html`；原 EFL 地址保留。

FPL 沿用 EFL 的页头 GW 切换、球场阵容与位置榜、左侧图表控制区、Radix 分组筛选、百分位画像、固定姓名列表格和赛程解析布局。球队队徽、普通球衣和门将球衣从官方来源缓存到同源 WebP，表格与图表复用这些资产。球队使用官方彩色 70px 队徽，避免部分默认白色队徽在浅底消失。

当前与下一轮的球员榜使用官方 `ep_this` / `ep_next`，已结束轮显示该轮实际分；更远轮次不虚构预测。11人参考阵容按位置人数和每队最多3人展示，不是完整15人预算方案。赛程综合档位为官方 FDR；进攻和防守档位按对手实际场均失球/进球分档，详细口径位于页面展开项。

FPL 使用官方 bootstrap-static、fixtures 和逐球员 element-summary：支持价格/球队/位置/分钟筛选、赛季与最近3/5/10次出场、球员场均表、可选指标散点图与 PNG 导出、同位置百分位、逐场记录、转会热度、球队表现、官方 FDR 矩阵、定位球与官方动态。价格、持有率、球队和状态均为当前快照，历史比赛不回填虚构的赛前信息。当前不提供本站 FPL 预期得分或预算组队。

`npm run data:fpl` 更新 FPL；`npm run test:fpl` 验证字段映射、双赛、分钟分母、缺失与真实零值、防守贡献门槛和实际快照。`npm run build` 同时生成两个模块，现有每日构建任务已接入 FPL。FPL 逐场原始数据本地缓存，成功快照保存于 `data/fpl/snapshot.json`，浏览器按需请求 `public/fpl/dashboard.json`，不加载 EFL 数据包。抓取失败且可确认同赛季时沿用旧快照，页面显示旧数据提示，否则构建失败。

GitHub Pages 静态版。GitHub Actions 每日北京时间 08:17尝试抓取并重新发布；调度可能延迟，源站统计发布也可能滞后，不承诺直播实时。

可视化支持球队 11 项指标及按位置筛选的球员指标自由组合。官方数据只统计已确认完赛；场均按实际出场次数计算。球员实际进球 / 90 使用官方累计分钟，xG / 90 使用 Statz 分钟；两源比赛覆盖可能有差异，出场数不匹配时不展示 xG。缺失值不计作零。

来源：Fantasy EFL 官方公开 players / squads / rounds / live 数据；Statz 三个联赛球队和球员 xG 页面。球队胜率、零封率、场均积分由逐场官方数据计算。

页面分别显示两类数据的成功抓取时间（北京时间），抓取时间不是源站统计截止时间。xG 抓取失败时保留旧快照及原时间；官方抓取失败则停止发布。

本地构建：npm ci && npm run build。生成结果位于 pages-dist/。

## 进阶指标与筛选 UI

所有筛选使用同一圆角控件及可滚动分组菜单，支持方向键、Enter、Escape。球员表按位置隐藏不适用列；混合查看时不适用单元格留空，适用项真实零值仍显示 —。

球队新增 Statz 同批比赛的 xGD/场、xG占比、xPts/场、积分超预期/场、进球超预期/场。xPts 使用源站逐场泊松模型结果，不根据赛季均值重算。来源：https://statz.ai/competitions/championship/xg 。抓取字段缺失时显示缺失，不填零。

球员新增进球+助攻/90、关键传球/90、射正/90、防守动作/90（解围+封堵+抢断+拦截）；门将扑救率=扑救/(扑救+失球)，分母为零时视为缺失。这些指标描述比赛表现，并非经过验证的预测模型；防守动作受战术影响，超预期指标可能随样本回归。建议结合至少900分钟门槛查看。

## 阵容与位置展示

图表对象通过左球员、右球队的分段按钮切换，整段可点击。推荐球队左右并排，阵容卡片显示本轮预期得分。场均表按位置移除无关列，并在所有视图隐藏黄牌、红牌、乌龙、失点和帽子戏法；这些底层数据仍保留用于真实 Fantasy 得分计算。动作得分是结合少量同位置先验估计的每场动作得分预期，不是次数、不含进球助攻及零封。

## 图表完整性与导出

坐标范围由当前全部有效数据的极值及边距自动计算，支持负数及小数刻度。图表保留所有有效数据点，姓名标签按空间避让，悬停可查看每个对象。缺失指标对象单独列出。

xG 姓名首先精确匹配；同联赛、同球队内，两源均唯一的“名字首字母+姓氏”允许匹配缩写，例如 Jack Fitzwater / J. Fitzwater。仍要求 Statz 出场数与官方确认比赛出场数一致，歧义不强行合并。

右上角可导出 1640×1888 PNG，包含当前标题、筛选条件、样本量、坐标、球衣/队徽和来源抓取时间。构建时缓存图表图片至同源 public/chart-assets，避免浏览器跨域限制；图片失败时仍保留该点并显示姓名缩写。运行 node scripts/test-chart-data.mjs 检查姓名缩写、歧义、极端值和刻度；CI 发布前也会执行。

## 图片性能优化与交互（2026-10-15）

先测量：144 张原图共 2,178,612 bytes，部分页面仍直接用 EFL 图片源。方案：构建时以 Sharp 缩到最大96×96（保留透明，不放大），编码 WebP quality82；所有阵容、排名、赛程、图表和下一轮数据的图片字段递归复用同源指纹文件。实测优化后521,488 bytes，体积减少76.1%，并非宣称加载耗时同比下降。首屏阵容图片优先解码，普通图片懒加载，图表距可视区250px内再加载；GitHub Actions 缓存已处理图片，避免重复抓取/转换。

提示框以两个带边框的浅蓝指标块突出数值。联赛单选菜单允许三个单项、三个两两组合和总计共7种集合，图表与场均表口径一致。场均表默认显示非门将，直接去掉扑救/扑点；查看门将时恢复相关列。推荐榜每页10人，在搜索工具栏右侧用左右按钮翻页，排名连续、位置切换重置第一页，焦点位于翻页控件时也支持左右方向键。

中文新闻：构建任务从 EFL 页面读取可用正文，优先保留选人相关内容。已核实的报道提供中文摘要与具体影响；新增报道用正文姓名匹配及保守伤停/红牌规则生成中文观察提示，不推断复出日期、不把普通曝光当作加分、不自动改模型分数。正文缺失则跳过；源站不可用时沿用带原日期的已保存摘要。每条保留原文链接。当前摘要与风险观察均以原文为依据，Fantasy影响与报道事实分开呈现。

验证：node scripts/test-dashboard-features.mjs 检查7种组合、中文来源、伤停规则和缩略图尺寸；浏览器验证10人翻页/位置重置、非门将删列、双指标提示框和WebP到PNG导出。现有图表完整性与轮次回归检查继续执行。

## 实时搜索、品牌与更新说明

浏览器标题为 Fantasy EFL Data。页签图标与导航logo原样取自官方站 https://fantasy.efl.com/favicon-32x32.png 和 https://fantasy.efl.com/apple-touch-icon.png，保存在public中，避免依赖额外域名请求。

个人数据去掉二次“选择球员”下拉：姓名输入实时展示符合当前联赛、位置、球队的结果，结果带队徽和球队名，点击或回车切换档案；支持方向键、Escape和无结果提示。左侧新增带队徽的球队筛选；比较门槛90/450/900分钟。球队筛选不缩小同位置排名参照组。档案横条用独立红黄绿配色，表格继续使用极浅的绿白红。

更新由.github/workflows/pages.yml在每日00:17 UTC（北京时间08:17）及push/手动触发，抓取后构建部署。任务可能排队；源站未更新则无新数据，源站失败按现有同赛季快照回退。浏览器加载的是构建快照，打开后不会自动获取新版本，需要刷新。

新闻由scripts/enrich-news.mjs处理：读取官方页面/最多12篇候选正文，过滤无关或正文不足140字符的文章，按发布日期保留最多5条。三篇已核实文章走URL+正文条件保护的预写中文分析；新文章按标题分类，正文匹配最多4名球员，再在包含姓名的句子查伤愈、罚下、伤停关键词，生成中文规则提示。其他只给按位置的观察模板。没有接入LLM，不是自动逐篇深度分析或完整翻译；规则可能漏识别或误判。不自动增减预期得分，抓取失败保留摘要原日期。


球队场均数据紧接球员表：官方 Fantasy 得分、进失球、联赛积分、胜率、零封率，以及 Statz xG/xGA/净差/预期积分；独立搜索、7种联赛筛选、列排序和同联赛浅色比较。个人数据已迁至 personal.html 独立入口，球员链接携带 player ID，支持直接打开与刷新。横条采用非线性色阶：0–25红、25–50橙至金黄、50–70金黄、70–85黄绿、85以上绿色。
